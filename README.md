# ОСНОВА — платформа подготовки к ЕГЭ

Рабочая full-stack платформа для регулярной подготовки школьников к ЕГЭ. Первая версия сфокусирована на биологии, но предметы, темы, задания и пробники не привязаны к одному курсу.

## Возможности

- индивидуальные аккаунты, безопасное хеширование паролей через `scrypt`, серверные сессии и роли;
- дашборд с прогрессом, серией, планом дня, слабыми темами и последними результатами;
- карта из 9 разделов биологии, вложенные темы и страницы с теорией;
- тренажёр для одного/нескольких ответов, соответствия, последовательности и краткого ответа;
- подбор сначала нерешённых заданий, возврат ошибок и базовые интервалы повторения;
- адаптивные тренировочные сессии с режимами «новое», «повторение» и «работа над ошибками»;
- отдельный учёт навыков, прохождения уроков и состава каждой тренировочной сессии;
- профиль с XP, точностью, историей и освоением тем;
- схема полноценных пробников с таймером и ответами;
- защищённая админ-панель со статистикой и управлением заданиями;
- адаптивный интерфейс, светлая/тёмная тема, без клиентского фреймворка и платных сервисов.

## Стек

- **Node.js 22+**, встроенный HTTP-сервер, `pg` и PostgreSQL `Pool`;
- **PostgreSQL** в production при наличии `DATABASE_URL`; SQLite остаётся fallback для локальной разработки и тестов;
- HTML/CSS/vanilla JavaScript SPA.

Приложение выбирает драйвер автоматически: `DATABASE_URL` включает общий PostgreSQL для всех production-инстансов, а без неё используется локальный файл SQLite.

## Локальный запуск

```bash
cp .env.example .env
# Node сам не загружает .env, поэтому экспортируйте значения при необходимости:
set -a; source .env; set +a
npm run seed
npm start
```

Откройте <http://localhost:3000>.

Демонстрационные аккаунты после seed:

- ученик: `student@ege.local` / `Student123!`;
- администратор: `admin@ege.local` / `Admin123!`.

Смените эти пароли или удалите демонстрационные аккаунты перед публикацией.

## Переменные окружения

| Имя | Назначение | По умолчанию |
|---|---|---|
| `DATABASE_URL` | строка подключения PostgreSQL (при наличии включает PostgreSQL) | — |
| `PORT` | порт HTTP-сервера | `3000` |
| `DATABASE_PATH` | путь к SQLite | `./data/ege.sqlite` |
| `SESSION_SECRET` | зарезервирован для подписи внешних интеграций; задайте длинное случайное значение | — |
| `NODE_ENV` | в `production` cookie получает флаг Secure | `development` |
| `EXAM_DATE` | дата экзамена в формате YYYY-MM-DD | `2027-06-05` |

## Команды

```bash
npm run dev     # разработка с автоматическим перезапуском
npm run seed    # идемпотентная загрузка оригинальных демо-данных
npm test        # проверка схемы БД
npm run check   # синтаксическая проверка JS
```

Миграции лежат в `migrations/`, а демонстрационные материалы — отдельно в `scripts/seed.js`.

## Render PostgreSQL

1. Создайте PostgreSQL в Render и подключите его к Web Service через переменную `DATABASE_URL` (значение не сохраняйте в Git).
2. Укажите build-команду `npm install`, start-команду `npm start` и `NODE_ENV=production`.
3. При каждом старте приложение само выполняет ещё не применённые PostgreSQL-миграции в транзакциях и фиксирует их в `schema_migrations`, затем идемпотентно добавляет отсутствующий базовый контент.
4. Настройте Health Check Path: `/api/health`. Endpoint проверяет запрос к БД, но не возвращает строку подключения или другие секреты.

SQLite и `DATABASE_PATH` предназначены только для локальной разработки/тестов. Не запускайте `npm run seed` как build-команду production: демо-пользователи production не нужны.

## Следующий этап

1. редактор тем/подразделов и полноценное редактирование заданий в админке;
2. экзаменационный движок: фиксация времени, навигация, подсчёт первичных/тестовых баллов;
3. автоматические резервные копии PostgreSQL;
4. персональный недельный план и прогноз балла;
5. импорт собственной базы заданий, химия, аналитика класса и ИИ-разбор ошибок.

## Безопасность

SQL-запросы параметризованы, сессии хранятся на сервере, cookies имеют `HttpOnly` и `SameSite=Lax`, доступ к админским API проверяет роль. Для production рекомендуется добавить reverse-proxy rate limiting, CSRF-токены для административных операций и email-подтверждение.
